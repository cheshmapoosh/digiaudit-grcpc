# ADR-0001: ردیف محافظ دیتابیسی برای هر ساختار سلسله‌مراتبی

- **وضعیت:** پذیرفته‌شده
- **تاریخ تصمیم:** ۱۴۰۵/۰۵/۱۳ برابر با ۲۰۲۶/۰۸/۰۴
- **دامنه:** ساختارهای درختی اطلاعات پایه نسخه دوم

## تصمیم

برای هر ساختار درختی مستقل، یک ردیف در جدول فنی زیر نگهداری می‌شود:

```text
masterdata_hierarchy_guard
```

ردیف‌های فعلی:

| کلید | ساختار تحت حفاظت |
| --- | --- |
| `ORGANIZATION` | ساختار والد و فرزند سازمان |
| `PROCESS` | ساختار مشترک فرآیند و زیرفرآیند |

فرآیند و زیرفرآیند دو جدول مجزا هستند، اما یک ساختار واحد محسوب می‌شوند؛ بنابراین Guard جداگانه برای زیرفرآیند ایجاد نمی‌شود.

## قانون اجرایی

تمام عملیات ساختاری زیر باید در همان تراکنش، پیش از خواندن یا اعتبارسنجی درخت، ردیف Guard مربوط را با `PESSIMISTIC_WRITE` قفل کنند:

- ایجاد گره؛
- انتقال یا تغییر والد؛
- حذف؛
- بازیابی؛
- ایجاد یا حذف رابطه والد و فرزند؛
- تغییر وضعیت مؤثر بر امکان والد یا فرزند بودن؛
- عملیات ساختاری گروهی، ورود اطلاعات، مقداردهی اولیه یا اصلاح مدیریتی.

ترتیب اجباری:

```text
شروع تراکنش
دریافت Guard Row
خواندن آخرین وضعیت ساختار
کنترل نسخه، والد، چرخه، وضعیت و وابستگی‌ها
اعمال تغییر
ثبت Business Revision در صورت نیاز
Commit یا Rollback کامل
```

قفل Java، `Caffeine`، قفل Cache متمرکز، قفل کل جدول و `@Version` به‌تنهایی منبع صحت ساختار نیستند.

## شمارش فیزیکال اصلاح‌شده

با این تصمیم، شمارش فعال به‌صورت زیر است:

- ۴۵ جدول کسب‌وکاری؛
- ۲ جدول فنی؛
- جمعاً ۴۷ جدول فیزیکال.

دو جدول فنی مجاز:

```text
document_temp_upload
masterdata_hierarchy_guard
```

این تصمیم فقط ممنوعیت قبلی «هر نوع جدول فنی Lock» و شمارش قبلی ۴۶ جدول را در همین محدوده اصلاح می‌کند. سایر محدودیت‌های مدل فیزیکال همچنان معتبر هستند.
